## Notes for the release

- **Lightning Proximity is gone** from the alert feed list. Users who had it
  on get the lightning guard switched on with the same tone, notification
  and speech choices (one-time migration of the browser's alert settings).
  The map layer no longer beeps on its own; screen-reader announcements now
  come from the guard.
- **Web Push for lightning** works on any server with VAPID keys — no
  extra setting. Each browser that ticks the box stores its location
  (rounded to ~1 km) and radii with its push subscription on the server; the
  server pushes a reported strike only to subscribers inside their own
  radius, throttled per subscriber and rate-limited per client. Self-hosters
  who used `PUSH_LIGHTNING_BROADCAST=true` keep the old send-to-everyone
  behaviour (now an override).
- **Push verification:** before a reported strike is pushed to anyone but
  the sender, the server matches it against its own Blitzortung connection
  (within 5 km / 30 s). The server opens that one WebSocket only while some
  subscription has opted in to lightning, keeps strikes only near opted-in
  stations, and backs off up to 5 min when it can't connect. Unconfirmed
  reports go back to the sender only.
- **Headless guard settings follow the displays:** they now travel with the
  indicators the browser already posts; Push to Rig Bridge only carries the
  pin and bridge-side switches. The relay card shows **Update Rig Bridge**
  when the bridge lacks the multi-display rules (`features` in
  /api/gpio/status).
- **Rig Bridge:** `gpio.pins.lightningOut` stays off by default (suggested
  BCM 25 / header 22, `P22` accepted on the setup page). New:
  `gpio.lightningHeadless` (off by default) runs the guard inside the bridge.
  The bridge needs updating for the multi-display hold and the headless
  guard; an older bridge still follows a single display (the app says so).
- Hardware-tested: nothing yet. Unit-tested logic, mock GPIO backend, fake
  Blitzortung sockets, and rendered UI tests; the live Blitzortung feed was
  checked from Node (bridge and server code). Not yet seen against a live
  storm or a real relay.
